## Application Paragraph

One project I am currently building is a plant succession monitoring dataset for disturbed urban edge habitats. I designed a repeatable field workflow with mapped monitoring sites, structured observation forms, disturbance-event tracking, photo protocols, normalized CSV schemas, and validation scripts. The project is intentionally staged: first make the field data reliable, then use it for ecological summaries, geospatial exports, and eventually computer-vision-assisted change detection. This has pushed me to think carefully about observation quality, uncertainty, taxonomic confidence, media organization, and how biodiversity data systems can support both human observers and later computational analysis.

## Seven-Day Public MVP

Day 1:

- Push this scaffold to GitHub.
- Add a short repository description and topics.
- Confirm `.gitignore` protects raw photos and private exports.

Day 2:

- Add 2-4 sanitized screenshots to the README if they are safe to share.
- Use captions that explain workflow, not just decoration.

Day 3:

- Replace sample rows with a tiny intentionally public subset of real data, or keep samples clearly labeled if real data is not ready.

Day 4:

- Run validation and paste the output into a short `README` section or GitHub issue.

Day 5:

- Add one simple plot or table from the walkthrough notebook.

Day 6:

- Publish the LinkedIn post.
- Pin the repository on GitHub.

Day 7:

- Use the application paragraph in outreach, cover letters, or the iNaturalist application.
